# macOS 14+ 原生应用设计与交付规格

## 1. 目标与边界

macOS 应用是「吐呐」的原生桌面端，不是 iOS 窗口的放大版。它必须提供调音、乐器、专业
分析、节拍器和设置五个完整入口，并与 Android/iOS 共用同一份 Rust 业务核心和 UniFFI
合同。

本阶段非目标：录音、音频文件保存/回放/导出、菜单栏常驻、云同步、手动选择音频设备、
后台持续麦克风采集。界面不得暴露这些未实现入口。

## 2. 平台与构建模型

- 最低系统版本：macOS 14。
- 处理器：Apple Silicon 与 Intel；Rust 静态库分别构建后合并为通用 macOS slice。
- `ios/TunarCore/tunar_core.xcframework` 同时包含 iOS 真机、iOS 模拟器和 macOS 通用
  slice；Swift 绑定仍由 UniFFI 一次生成，禁止手改。
- macOS 目标使用独立 Bundle ID 和独立 `UserDefaults` 容器，不迁移或覆盖移动端数据；
  所有默认值与移动端一致。

## 3. 桌面信息架构

根窗口使用 `NavigationSplitView`：

- 左侧固定五项侧栏：调音、乐器、专业分析、节拍器、设置。
- 右侧为单一内容区；窗口最小尺寸保证侧栏与核心控件均可用。
- 调音页点击频谱预览直接选中同一个「专业分析」侧栏项，不创建新窗口或第二份状态。
- 宽窗口下专业分析采用主图与连续时间图谱并排；空间不足时按主图、摘要、连续图谱纵向排列。

五个入口共享 Aurora 颜色、圆角、数据胶囊和语义状态；桌面端不复制移动端底部标签栏，也
不照搬手机纵向比例。

## 4. 核心状态与流转

### 4.1 采集

`CaptureHub` 仍是唯一采集所有者，关键状态为：

- `references`：当前需要采集的页面订阅数；
- `generation`：异步启动令牌；
- `running`：音频引擎是否已成功提交；
- `config`：A4、噪声门限、唱名、调式和律制。

首个订阅者触发异步启动，后续订阅者共享同一路输入。最后一个订阅者释放时使未完成令牌失效，
停止 tap、音频引擎与分析线程。切页或窗口失活不得让旧初始化重新打开麦克风。

macOS 使用 `AVAudioEngine` 输入节点，不创建 `AVAudioSession`。系统音频回调只写入构造期
分配的固定环形缓冲；Rust `analyze`、数组构造和设置同步在分析线程执行。

### 4.2 调音与乐器

调音与乐器页完全消费 Rust `AnalysisFrame`。噪声门限、两帧确认、滞回和无限保持由 core
决定；macOS 不增加清空超时。音叉频率来自 core 的 `ReferenceTone`，收起选择窗后继续
播放，离开调音页或窗口失活时停止。

乐器页与 iOS 共用同一套线稿图示源文件（琴头、古琴、管乐图与管乐表格）：

- 乐器切换条六格平铺并带线稿图标。吉他控件区有“6-in-line / 3+3”琴头分段与自动/手动分段；
  图示卡片中央为琴头线稿，弦音按钮分列两侧并以虚线连到各自弦轴；古琴为一排弦音按钮加古琴线稿，
  点按古琴图上的弦即激活对应按钮。行为规则见 spec-ui §2a。
- 竹笛、洞箫、尺八统一使用下述管乐表格（以洞箫为基准）；竹笛无孔制切换，尺八三列为乙音/甲音/大甲，
  且不提供唱名拖动转调与十二音详情。

- 洞箫提供 G/F 调，8 孔默认并可切换 6 孔；顶部“筒音作 X”仅显示唱名映射结果，不是选择器。
- 主视图保留 7 个基础孔位行，十二音详情独立保留 12 个基础孔位行；两者右侧均为
  **低音（缓吹）**、**中音（超吹）**、**高音（急吹）**三列。三列都显示 core 按各音区
  实测孔位返回的指法（中音多数同低音，高音不同）；指法图未覆盖的格视觉留白且不可点，
  禁止复制低音孔位或通过八度/五度偏移合成其指法、音名和频率。
- 左侧恰好一支完整大型竖向洞箫，右侧为三音区列，不按指法类型分轨。8 孔管体恰好
  显示 8 个孔，6 孔管体恰好显示 6 个孔；开、闭、半孔可辨识。第一孔向侧方轻微偏移以贴近
  流行洞箫实物孔位，背孔保持管身中轴并使用专色。
- 每个基础指法行按 `anchor_hole` 与最上方开孔孔心严格对齐，全闭行锚定底部出音口，并显示贯穿管身和三列
  的辅助线；无对应七声指法的物理孔位线保持空白。叉指或半孔只在单元格显示小型“叉”或“半”标记。
- 单元格使用固定音名和独立唱名徽标，禁止 `D3·5`。点击音名或唱名徽标把完整指法固定到大图，
  优先于实时识别，再点一次交回实时。纵向拖动唱名徽标越过整档时立即连续更新并播放位移动画，
  主表在七个自然唱名档间循环，详情独立在 12 个半音档间循环，均可由作 5 一次持续到作 2；
  松手提交最近离散档并吸附。落档更新
  唱名与“筒音作 X”，并原子重筛七声主表为完整 `1–7`；十二音详情孔位保持稳定。
- 点击主视图标题行空白区域或“十二音详情”按钮，以大尺寸 sheet 打开独立 12 半音详情，
  禁止在主视图原地展开。详情复用同一套“一支大洞箫 + 三音区列”几何关系；sheet 必须有
  始终可见的关闭操作。
- 主视图和详情复用同一个 `CaptureHub` 与同一 `AnalysisFrame`，不得因 sheet 创建平行采集
  会话或第二路分析；两者各自的滚动位置、单元格预览与交互状态独立。关闭详情后主视图保持打开前状态；
  两个视图都以单元格点选高于实时识别，再点一次同一单元格才交回实时。
- 两个视图的三列区域都随实时命中音自动横向滚动，尽量把命中列带到该区域中心；这是趋势算法，
  位移夹在合法滚动范围内，边界处只滚到能滚的最大值。点选与手动滚动不触发自动滚动。
- 主视图和详情各自只能显示一支完整大型洞箫图，图中展示 core 主指法，不宣称逐半音唯一权威；
  乐器形制和流派可能存在替代指法。
- 竹笛和尺八暂保持旧交互，不显示洞箫的 8/6 孔切换、唱名徽标拖动或独立十二音 sheet。

### 4.3 专业分析

专业分析与调音共享 `CaptureHub` 和同一个 `AnalysisFrame`：

- 主图可切换乐音/全频频谱、约 12 秒音高轨迹和当前窗口波形；
- 固定峰值只被更强帧抬高，重置只清峰值；
- 暂停冻结主图、峰值、轨迹和连续时间图谱，恢复后的音高轨迹从新段开始；
- 连续时间图谱保留刻度、强度色标和 256 行历史；
- 不产生第二次 FFT，也不记录音频。

### 4.4 节拍器与设置

节拍调度、tap tempo 和每拍重音由 Rust `Metronome` 执行；macOS 只用 `AVAudioEngine`
播放 core 渲染的样本并呈现 tick。十二种音色顺序和默认强弱拍与移动端一致。

设置使用独立桌面端 `UserDefaults`，默认 A4 440Hz、噪声门限 -45dBFS、12-TET、跟随系统
主题和开启触觉选项（macOS 无触觉硬件时静默无操作）。任何设置变更立即下发到共享采集引擎。

## 5. 权限与失败回退

- 首次进入需要采集的页面时请求麦克风权限；拒绝后显示原因和打开系统设置的按钮。
- 输入设备返回 0Hz、0 声道或启动失败时，本次启动安静失败并释放资源；页面保留可重试状态，
  不安装无效 tap，不崩溃。
- 扬声器不可用时音叉或节拍器停止并保持 UI 可操作；不得影响麦克风分析。

## 6. 验证资料

- Rust 既有合成信号、律制、预设和节拍测试继续作为跨端业务真值。
- macOS 单元测试覆盖五项导航、默认入口、桌面布局决策、频谱坐标/峰值保持、采集格式和
  启动令牌，并覆盖洞箫 8 孔默认/6 孔切换、单一大图 + 低/中/高三音区列、
  core 按三音区实测孔位返回（8 孔 19/32 条）、指法图未覆盖的格留白且无合成数据、
  最上开孔锚点与空白线、点选优先于实时识别、命中音区列自动趋势居中、主表七档/详情十二档
  吸附手势和独立详情状态。
- 构建验收覆盖 Apple Silicon 与 Intel 通用库、macOS app 和 macOS 测试 target。
- 手动验收覆盖权限允许/拒绝、五页切换、A4 参考音回采、专业分析暂停/重置和节拍器播放；
  洞箫额外验收大 sheet、主视图与详情共享采集但状态独立，以及竹笛/尺八旧路径未回归。

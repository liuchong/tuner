# 专业频谱峰值重置与节拍器音色验收

## 范围

本轮只增加专业频谱峰值保持线的手动重置，以及节拍器内置音色。峰值重置不清空实时数据；
节拍器定时、拍号、重音规则和默认音色不变。不增加音色试听按钮、独立音色音量、自定义导入、
外部资源文件、权限或数据库迁移。

## 场景 1：实时状态下重置峰值保持

假如专业频谱已经记录一帧 -20dBFS 的历史峰值，
并且当前实时频谱、连续时间图谱和暂停状态已有确定内容，
当用户点击「重置峰值」，
那么全部峰值保持桶清到 -80dBFS，
并且实时频谱、连续时间图谱和暂停状态保持不变；
当下一张有效频谱帧到达，
那么峰值保持从该帧重新累计。

## 场景 2：暂停状态下重置峰值保持

假如专业频谱已经暂停并保留历史峰值，
当用户点击「重置峰值」，
那么峰值保持桶清到 -80dBFS，
并且页面仍保持暂停，实时频谱与连续时间图谱仍冻结；
当用户继续后收到下一张有效频谱帧，
那么峰值保持才重新累计。

## 场景 3：音色列表按常用程度稳定排序

假如用户打开重拍或弱拍音色选择器，
那么 Android 与 iOS 都按以下顺序显示且名称一致：

1. 机械节拍
2. 木块
3. 电子滴声
4. 拍板
5. 边鼓
6. 小鼓
7. 牛铃
8. 踩镲
9. 拍手
10. 沙锤
11. 低鼓
12. 铃声

重拍默认仍为铃声，弱拍默认仍为机械节拍。

## 场景 4：全部音色可安全生成并注入

假如应用以 44100Hz 构建内置音色缓存，
当逐一生成十二种音色，
那么每种 PCM 波形非空、只包含有限数值、峰值不超过 0.95，
并且任意两种音色的完整波形不相同；
当用户选择任一音色作为重拍或弱拍，
那么对应波形立即注入现有节拍器引擎，播放中的节拍定时不重建、不漂移。

## 场景 5：保存值兼容与异常回退

假如设备保存的是已有 `click`、`beep` 或 `bell` 标识，
当升级后恢复节拍器状态，
那么仍恢复为同一种音色；
假如保存值未知或损坏，
那么重拍安全回退为铃声，弱拍安全回退为机械节拍，不得崩溃。

## 双端一致性门禁

- Android `TickSoundKind.entries` 与 iOS `TickSoundKind.allCases` 的顺序、名称和保存标识逐项对应。
- 十二种合成函数的采样率、样本数、频率、包络、增益和归一化参数逐项对应。
- Android 与 iOS 均覆盖峰值重置、音色顺序、波形安全性、选择注入和异常保存值回退。
- 本轮不修改 Rust 节拍定时、UniFFI 接口、权限、安装配置或帮助命令。
